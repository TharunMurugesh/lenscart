# LensCart: an online fashion store with a trained vision model

**Event:** Tech-Bees Computer Vision 2026, Presidency University
**Team:** Code Explorers. Vinay G (20241CSE0759), M Tharun (20241CSE0692)
**Code:** https://github.com/VinayG759/LensCart

## 1. Title and abstract

**LensCart: a fashion e-commerce store whose product attributes come from a trained,
explainable vision model.**

We trained a multi-task convolutional neural network (EfficientNet-B0) on 28,270 product photos
from the public Fashion Product Images dataset. From one photo it predicts four attributes: article
type (49 classes), base colour (18), gender (5) and usage (4). On 4,824 held-out test photos it
reaches 90.4% accuracy for article type, 70.7% for colour, 93.1% for gender and 92.4% for usage.
The model runs inside the shopper's browser (ONNX Runtime Web), so no image leaves the device.
For each answer it shows a heat map of the image regions that drove it. The store is built in PHP
and MySQL. It uses the model for search by photo, for auto-filling product details when an admin
adds a product, and for an on-page check that compares the model's reading with the catalogue
label.

## 2. Problem and proposed solution

**Problem.** An online fashion store depends on correct product attributes (type, colour, who it
is for, occasion): they drive filters, search and recommendations. Typing them in by hand for every
listing is slow and error-prone, and shoppers cannot search with a photo of what they want.

**Solution.** One trained model reads these four attributes from the product photo and is used in
three places in the store:

1. **Search by photo** (`photo.php`): a shopper uploads any clothing photo; the model's answers
   rank matching products in the store.
2. **Admin auto-fill** (`admin/product_edit.php`): choosing a product photo fills in type,
   colour, gender and occasion; the admin checks them and saves.
3. **Label check on every product page**: the model reads the product's own photo and shows,
   per attribute, whether it agrees with the catalogue label, with the heat map.

Every answer carries a confidence and a heat map, so a person can see why the model decided.

## 3. Database structure

MySQL / MariaDB, five tables (`site/sql/schema.sql`). Row counts are from the seeded database.

| Table | Columns | What it stores | Rows |
|---|---|---|---|
| `users` | id, name, email (unique), password_hash, role (user/admin), created_at | Shoppers and the admin. Passwords stored only as `password_hash` (bcrypt) | 31 (1 admin, 30 demo customers) |
| `products` | id, name, articleType, baseColour, gender, usage, masterCategory, subCategory, price, stock, image, created_at | The catalogue. The four attributes are the model's four outputs | 1,500 |
| `orders` | id, user_id → users, total, status (placed/shipped/delivered/cancelled), address, created_at | One row per checkout | 240 |
| `order_items` | id, order_id → orders, product_id → products, qty, price | Lines of each order; price at the time of purchase | 590 |
| `views` | id, user_id → users, product_id → products, ts | Product pages a logged-in user opened; drives "Picked for you" | 837 |

Relations: an order belongs to a user and has many order items; each order item and each view
points to a product. The store reads these for recommendations ("Picked for you" from a user's
most viewed type and colour; "Customers also bought" from products that appear in the same
orders) and for the admin dashboard (revenue per day, revenue by article type, average order
value, top products, low stock).

## 4. Sample dataset

- **Source:** Fashion Product Images dataset by P. Aggarwal (Kaggle), product photos and labels
  from an Indian fashion e-commerce catalogue. 44,446 records.
- **For the model:** 40,410 images in 49 article types after cleaning (section 5), of which 40,406
  have an image file.
- **For the store:** 1,500 products sampled from the cleaned set (stratified by article type,
  seed 42): 717 apparel, 355 footwear, 428 accessories, in 45 article types. Innerwear is not sold
  in the store, although the model still recognises those four classes. Product names, photos and
  the four attribute labels are the dataset's own.
- **Synthetic (made up for the demo, and labelled so on the site):** prices (₹99 to ₹9,899, a fixed
  range per article type), stock levels, the 30 customer accounts, 240 orders spread over 60 days,
  and 837 product views. Generated by `scripts/build_site_data.py`.

## 5. AI/ML implementation

**Cleaning.** Kept the Apparel, Footwear and Accessories categories, then article types with at
least 100 images (49 types, 40,410 images). Colour: 18 colours with at least 300 images; other
colours and "Multi" are masked (2,479 labels). Usage: Casual, Sports, Ethnic, Formal (126 labels
masked). A masked label is skipped in that head's loss and metrics only. Season and year are not
used because they are not visible in a photo.

**Split, made before any training.** Stratified by article type, seed 42, grouped by product name
so the same product never appears in both train and test. Near-duplicates were then removed from
validation and test: an image was dropped if a training image with the same article type and
colour was within perceptual-hash distance 4 (2,468 dropped). Final: **train 28,270, validation
4,844, test 4,824.**

**Model.** EfficientNet-B0 pre-trained on ImageNet (4.1 M parameters), global-pooled 1,280-value
feature vector, dropout 0.2, then one linear layer per attribute (49 / 18 / 5 / 4 outputs). Input
224 × 224, padded to a white square.

**Training.** Class-weighted cross-entropy per head (weights from the training split only). Stage A:
backbone frozen, 3 epochs. Stage B: whole network, up to 15 epochs, cosine learning rate, early
stopping on the validation score (mean macro F1 of the four heads). Best epoch 15, validation score
0.7960. Training took 1,231.7 s on an NVIDIA RTX 4050 laptop GPU (6 GB).

**Test results** (4,824 held-out photos, run once; 95% confidence intervals from 1,000 bootstrap
resamples; `results/test_metrics.csv`, `results/test_ci.csv`):

| Attribute | Test images | Accuracy (95% CI) | Macro F1 (95% CI) | Top-3 accuracy |
|---|---|---|---|---|
| Article type | 4,824 | 90.4% (89.5–91.1) | 0.859 (0.844–0.871) | 98.6% |
| Base colour | 4,523 | 70.7% (69.4–72.1) | 0.640 (0.621–0.658) | 92.3% |
| Gender | 4,824 | 93.1% (92.4–93.8) | 0.818 (0.792–0.841) | – |
| Usage | 4,813 | 92.4% (91.6–93.1) | 0.859 (0.845–0.873) | – |

Macro F1 is the main metric because the classes are imbalanced (the largest kept type has 67 times
more images than the smallest). Weakest article types: Tunics (F1 0.31), Flats (0.38), Kurtis
(0.51). Most frequent confusions: T-shirts vs Tops, Sports vs Casual Shoes, Flats vs Heels, Kurtas
vs Kurtis.

**Why train our own model** (validation, short 6-epoch schedule, `results/table5_backbones.csv`):
mean macro F1 of our EfficientNet-B0 0.778, ResNet50 0.744, FashionCLIP linear probe 0.771,
FashionCLIP zero-shot (no training) 0.576.

**In-browser inference.** The trained network was exported to ONNX (`site/ai/lensnet.onnx`) and runs
in the browser with ONNX Runtime Web (WebAssembly, `site/ai/lensai.js`). PHP never sees the photo.
Measured in Microsoft Edge on the team laptop (Intel i5, no GPU) during testing: about 1.2 s for the
first photo on a page (includes loading the model), then about 0.2 s per photo.

**Heat maps.** For each attribute the page draws a class activation map (CAM): because the model is
backbone → average pool → linear layer, the map shows how much each image region contributes to the
predicted class. A "focus" percentage reports how much of that heat lies on the garment rather than
the background. A heat map shows where the evidence was, not proof of how the model reasoned.

**Explore it live:** `model.php` ("Our AI model") shows the data steps, training curves, confusion
matrices and a Test mode that runs the model on random held-out test photos next to their recorded
labels.

## 6. Technology stack

- **Store:** PHP 8.3 (tested on XAMPP 8.3 with MariaDB 10.11), MySQL/MariaDB through PDO with prepared statements, plain
  HTML/CSS/JavaScript, Chart.js 4.4.1 (admin charts), Lucide icons. All libraries are stored in the
  site folder; no CDN.
- **Model in the browser:** ONNX Runtime Web (WebAssembly).
- **Training and data tools:** Python, PyTorch, timm, scikit-learn, pandas, ImageHash.
- **Security basics:** passwords hashed with `password_hash`, session id regenerated at login, CSRF
  token on every form, server-side validation, uploads checked as real JPG/PNG/WebP images under
  5 MB and saved under random names, errors logged instead of shown to visitors.

## 7. Deployment

- **Local (XAMPP):** copy the `lenscart` folder into `htdocs`, create a database, import
  `lenscart_db.sql` (schema and seed in one file), and open `http://localhost/lenscart/`.
- **Web hosting (web-a2z.com):** upload `lenscart_site.zip` (made by `scripts/package_site.py`)
  and extract it. Create a MySQL database and import `lenscart_db.sql` in phpMyAdmin. Then set the
  four database values in `inc/config.php`. The site starts from `index.php`. The model needs no
  server software beyond static file hosting.
